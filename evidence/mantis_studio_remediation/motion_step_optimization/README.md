# Exact frozen-parameter motion-step optimization

The first optimization removed decoder loading and repeated blank-state initialization from timed camera processing. The integrated observation trial still lost freshness: ordinary camera gaps of roughly 0.4–0.6 seconds require many 0.02-second neural steps, and every five-step `simulate()` chunk rebuilt fixed parameter views, mapped repeated stimuli and retained intermediate states.

This second change builds the frozen official parameter API once, maps each held retinal image once with the official stimulus object, and calls the official `_next_state()` for **every original integration step**. It retains the final state. It preserves the Euler equations, edge scatter-add order, all 45,669 neurons, decoder weights, visual preprocessing, 0.02-second step, causal image hold, 0.65-second reset gap and 0.5-second warmup. Changed or unfrozen parameters are rejected before stepping. It adds no steering or control authority.

## Actual comparison

`profile_step_equivalence.json` is the byte-identical receipt from one serialized CPU run: original, first optimization, then second optimization. Thirteen captures use independent texture seed 20271, velocity [6, −4] pixels/second, repeated 0.45/0.55-second intervals, one 0.70-second gap reset, and four additional explicit resets per implementation. Nine observations per implementation passed the unchanged sensor warmup rule; this is not a count of live controller-fresh observations.

Every full dynamic state tensor, all 2×721 decoder values, restored initial tensors, response clocks, validity decisions and population summaries matched **bit for bit** against both earlier implementations. Maximum differences were zero. Digests of every compared final state and decoded field are included; full arrays were compared in memory and are regenerated by the runner.

| Measurement | Original | First optimization | Second optimization |
| --- | ---: | ---: | ---: |
| Median neural processing for long intervals | 0.288063 s | 0.335434 s | 0.251734 s |
| Median complete raw-motion processing for long intervals | 0.338132 s | 0.391082 s | 0.301808 s |
| First timed capture | 2.279584 s | 0.075097 s | 0.045218 s |
| Capture with gap reset | 0.496632 s | 0.052586 s | 0.022741 s |
| Median explicit reset | 0.460088 s | 0.000056 s | 0.000036 s |

The second implementation has lower measured median cost than both earlier versions in this sequence. These are ordered, single-machine measurements: cache/order effects, scheduling and thermal variation prevent attributing every difference to code. Total raw-motion time includes the Farneback comparison, but excludes rendering, YOLO, target-mask guidance, recording and the integrated scheduling loop. It is not a real-time guarantee. Initialization still takes time; decoder construction/evaluation finishes before accepting captures.

**No accuracy improvement is claimed.** Bit-exact output preservation also preserves the original negative neural benchmark. The earlier [frozen motion evidence](../../mantis_studio/motion/README.md) and [first optimization evidence](../motion_optimization/README.md) remain unchanged. Live controller usefulness and deadline compliance require separate combined evaluation.

## Reproduce or verify

All three measured module snapshots are included. The adapted runner reads those snapshots, verifies their digests plus supporting repository source and locked manifest digests, uses the actual pretrained checkpoint, and writes only to a new output directory. It also records whether the live implementation still matches the measured second snapshot.

From the repository root, in the documented Flyvis environment with the locked model acquired:

```sh
python -B evidence/mantis_studio_remediation/motion_step_optimization/verify.py
python -B evidence/mantis_studio_remediation/motion_step_optimization/profile_step_equivalence.py \
  --manifest models/flyvis_0000_000.manifest.json \
  --output results/motion_step_optimization_recheck01
```

The first command checks compact evidence integrity without loading the model. The second performs the full three-implementation comparison; run it without other model or simulator jobs. The original receipt is never overwritten. `packaging.json` lists source, model, installed-runtime-source and artifact hashes. No raw video, full neural recordings or model weights are distributed here.

The neural network, parameter/state APIs and pretrained DecoderGAVP are from [Flyvis, TuragaLab](https://github.com/TuragaLab/flyvis); [upstream notices](../../../THIRD_PARTY_NOTICES.md#flyvis) apply. The existing nominal flow-unit transfer remains an uncalibrated Sintel-to-simulator assumption.
